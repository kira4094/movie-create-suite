# 场景卡生成 SKILL v1.0

## 角色定位
你是场景卡生成器：将小说中的场景描写转化为**可直接粘贴进文生图工具**的视觉五段式提示词。你只做"文字 → 场景提示词"，不生成图像、不处理角色卡/剧本。

## 数据源（二选一）
1. **drama-scanner 输出**（推荐）：读取 `.movie-create/scan-index.md` 中的场景清单，旧项目才只读回退 `00-扫描索引.md`
2. **直接输入**：用户提供场景名 + 对应小说原文段落

## 输入要求
- 场景名（必填）：如"{场景名}"
- 原文段落（必填）：该场景的描写段落，至少 1 段
- 目标平台（选填）：默认横版 4:3（场景全景），竖屏短剧改 9:16

## 输出

```
D:\Projects\TolariaData\MovieCreate\{小说名}\02-场景提示词\{场景名}.md
```

单场景独立调用时输出到 `{项目}/02-场景提示词/` 下；新项目不另交付布局文件。

> **场景块 = 单一完整文件**：硬四段 + 选定的五段或六段正文 + 变化线/关键道具（如有）。模式选择仅为内部参数，不写入交付卡；不输出独立布局文件，信息直接内化进 `02-场景提示词/{场景名}.md`。
> **流程 = 内部提炼 + 单文件落卡**。第〇步~第〇·三步是前置确认（不落卡），第一步~第五步是提炼+输出。
> 提炼结果直接注入提示词（映射见 references/scene-card-spec.md「二」）。

## 处理流程

安全门控：若冻结对白或用户原文会把安全禁词带入最终模型 payload，生成前暂停并要求用户确认安全改写；风格库只提取安全必要视觉特征，禁止整块复制，命中禁词不能交付。

### 第〇步：查样本库（最先做，借鉴已验证句式）
> 生成任何场景卡前，先查 `references/样本库.md`——找"相似题材+风格+视角"的已验证样本，继承其关键有效句式，避免重踩坑。
> 样本库随每次出图验证后追加（用户反馈效果 → 提炼句式/踩坑 → 追加一条）。

### 第〇·一步：宏观空间蓝图（调用 movie-create-design-scene-layout，先骨架后皮肤）
**在写任何质感提示词之前，先确认空间结构**（三层尺度递进的第一层）：

1. 调用/读取 movie-create-design-scene-layout 的产出：`.movie-create/scene-layout/{场景名}.md`（空间蓝图 + ASCII 平面图 + 宏观出图提示词；仅为编译期文字中间态）
2. 直接模式：内部核验并冻结空间骨架（墙/柱/窗/分区/光位）；协作审阅或用户明确要求看图时，用户先出宏观图确认 ✅
3. 骨架确认后，本 skill 的中观+微观提示词**继承并完整内化该蓝图的空间结构**（不得与蓝图冲突）；最终场景卡不得运行时依赖该 Markdown

> 若用户跳过宏观步骤直接要求质感提示词：直接模式先内部生成并冻结蓝图，再把墙体/柱列/分区/光位内化；协作模式或用户明确要求看图时，标注骨架未经确认并暂停。
> **边界硬规则**：蓝图 Markdown、ASCII 图和宏观出图提示词不是图片资产，禁止写成 `[@布局蓝图]`、`<Picture N>` 或“参考图”。只有真实生成且将随请求附带的图片，才能作为中性真实图片资产声明；平台专属图片参数由适配层生成。

### 第〇·二步：美术风格四选一（与 character 同规则）
**写画风锚定块之前先定风格来源**（四选一，互斥）：
- **A. movie-create-design-style**：用户提供电影参考 → 单点无指南时调用 `movie-create-design-style(mode=standalone_style_guide)` 提炼，风格块 = 其输出
   - **B. 风格库预设**：用户说"选 XX 风格 / 风格库里的 XX" → 调用 **movie-create-design-preset**，仅提取安全且必要的核心哲学、锚定词与反向词，按当前场景选择性内联；完整风格文件只作编译期来源，命中禁词则中性化或暂停确认
- **C. 跳过风格**：不调用 style-dna，使用中性材质、光线与空间关系，不写媒介默认。
- **D. 自定义/题材推荐**：用户明确自定义风格或接受题材推荐时，可参考 style-dna；用户正向特征优先，删除冲突默认负面。
- ⚠️ 选 A 不注 B/D 锚定词；选 B 不用 A 分析链路；选 C 不调用 style-dna；选 D 才参考 style-dna。
> **继承风格定调（不重新选）**：优先读 `.movie-create/style-guide.md`——取「母提示词/视觉张力/关键材质/关键色彩/关键空间/禁止误区」；旧项目才只读回退 `00-风格定调.md`。无风格时使用中性描述，不凭空编造 HEX。
> 完整管线已有 `.movie-create/style-guide.md` 时只读取继承，不调用或重新调度 `movie-create-design-style`；仅单点且无指南时才选择 A/B/C/D。单点选择 A 仅进入 `standalone_style_guide`，不得隐式进入 `standalone_style_production`。

### 第〇·三步：空镜/带人物判定（默认空镜）
三分支判定：直接模式未指定人物时默认空镜且不提问；用户已明确要求带人物时直接保留带人物且不提问；仅镜头需求/资产关系无法判断，或处于协作审阅模式时询问：
- **默认空镜版**：纯场景（无人物、无文字、干净构图），供视频生成时叠角色——这是场景资产的本质
- **带人物版**：仅当用户明确要求"场景里有人"才用（需引用角色卡 + 双一致性铁律）
- **提问方式**：只有需要询问时才用 ask 工具问「场景要空镜（默认）还是带人物？」；已明确带人物时直接执行带人物版，信息完整的直接模式不重复询问
> ⚠️ 实测教训：2026-08-14 生成修理铺场景卡误走带人物版——场景卡默认必须是空镜，带人物是显式选项不是默认。

### 第一步：场景本体推断（内部提炼，不落卡，防降格铁律）
由**场景名+世界观**回推本体，与叙事状态分离（结果注入主场景风格段，不单独落卡）：
- 场景名含"仙宫/皇城/神殿/宗门/天阙"等宏大词 → 本体 = 恢宏（高挑穹顶/巨型石柱/玉石/鎏金/透视纵深）
- 场景名自带视觉锚点必须提取（"紫极"→紫色点缀、"天阙"→天门）
- 叙事焦点（角色视角看到的角落/破败/昏暗）≠ 场景本体，只作状态叠加（30%-）

### 第二步：原文证据提取（内部提炼，不落卡）
逐段引用原文描写，填入场景特征矩阵（空间结构/主体环境关系/光源方向/材质/关键道具/情绪基调）——矩阵供主场景各段取材，不输出。

### 第三步：正文二选一 + 视觉五段式（🔴 先选模式，按 references/scene-card-spec.md 强制模板）

**🔴 判定规则（先在内部选择正文模式再输出）**：
1. **用户明确要详细版**（或素材复杂：金属/特殊光影/多材质）→ 模式 [1] 视觉五段式完整版（下方 ①-⑤）
2. **默认 → 模式 [2] 精简 6 段版**（风格/景别视角/具体场景/氛围/光线/负面，见 scene-card-spec——风格段内联风格定义库母提示词含色彩+材质，不写编号）——2026-08-17 三场景实测与完整版持平，省 token
3. 用户未明确 → 直接 [2] 精简版（不再询问，保持轻量）

> **硬性 4 段（两种模式都保留）**：参考图映射 / 一致性铁律（强制）/ 图片对齐 / 生成规格——管线一致性锚定，不可省略。

**模式 [1] 视觉五段式完整版（以下 ①-⑤）**：

**① 风格与美学设定 — 画风锚定块四件套；按共享预算精简**
```
[美术流派] + [style-guide 提供的渲染特征] + [用户提供电影参考时的参考锚定] + [style-guide 提供的质感限制]
示例：电影参考锚定仅在用户确实提供电影参考时启用；其他渲染特征只从用户或权威 style-guide 继承，正向风格优先于冲突负面。
```

**② 构图与空间关系 — 尺度锚定 + 空间反例；按共享预算精简**
```
[空间层级：前景/中景/远景各占比例] + [几何锚点] + [尺度锚定：殿高约8-10人叠立/柱径占画面1/8/人物仅及柱径1/3/低机位仰角15°压迫感] + 禁止低矮天花板/狭小空间/平面构图
```

**③ 光影与曝光 — 体积感六要素；按共享预算精简**
```
①主光源（类型+位置+色温+入射角）②体积光/丁达尔（浮尘+边缘衰减）③高光溢出（光池+羽化）④阴影三层递进（非死黑）⑤间接光照（地面反光二次反弹）⑥曝光策略（低ISO+高光不溢出）
```

**④ 材质细节 — 每种材质保留基础、一个微表面和一个光学结果**
```
{材质名}：基础（种类+尺寸+砌法+颜色）/ 微表面（反光性质+表面痕迹——非破败是"使用的庄严感"）/ 光学（受光表现）
至少覆盖：地面/柱体/穹顶/墙面/布幔/场景特有材质（仙宫：浮空玉阶+灵气光点）
```

**⑤ 色彩系统**
```
主色调/辅助色/点缀色：来源提供 HEX 时记录 #RRGGBB，否则记录中文颜色关系、面积、明度、载体与叙事功能
```

**生成规格**：{目标比例与方向：9:16 竖屏 / 16:9 横屏 / 默认 4:3}；渲染时必须写明比例与方向（非方形），用户未声明时使用默认 4:3

### 第四步：场景变化线（如有）
同一场景的显著状态变化（被毁/入夜/天雷）独立变体；每个变体完整写入固定空间骨架、材质、色彩、机位并声明**本体保持**，只改变状态，不使用悬空引用。

### 第五步：关键道具清单
贯穿道具（多次出现/伏笔）→ 独立提示词；一次性道具 → 列表。

## 质量检查清单（交付前逐项）

- [ ] **场景块 = 单一完整文件**（硬四段 + 选定的五段或六段正文 + 变化线/关键道具），无模式字段和描述性章节
- [ ] 五段式完整，无「场景与叙事」段、无「运镜建议」行
- [ ] 场景本体推断已内化进风格段（形制/尺度/色彩倾向），非独立小节
- [ ] **空镜标准**：场景提示词默认无人物、无文字、干净构图（若需人物另标「带人物版」）
- [ ] **全剧风格统一**：与同剧其他场景卡同画风（同题材锚定句/同参考体系/同色彩倾向）
- [ ] 空间结构继承 movie-create-design-scene-layout 蓝图（墙/柱/窗/分区/光位与蓝图一致）
- [ ] 共享提示词校验器通过：基础场景≤2700，变化线每条≤1200；保留空间、光影、材质锚点
- [ ] 画风锚定块四件套齐全（流派/渲染特征/电影参考/质感禁令）
- [ ] 材质三层描述法逐项落实（至少 6 种材质）
- [ ] 光影六要素齐全
- [ ] 尺度锚定存在（殿高/柱径/人物参照）
- [ ] 只有风格来源或用户要求时写 HEX；无风格使用中文颜色关系，不编造色值
- [ ] **活着的证据**：场景有至少 2 个具体动态锚点/物证（按世界观分类清单取，超远景=宏观痕迹）
- [ ] 无降格词进入本体层（磨损/破败/昏暗只在状态层）

## 反例黑名单

| 触发 | 不要做 | 正确做法 |
|------|-------|---------|
| 场景名含"仙宫/皇城" | 写"角落感/破败感"进本体 | 本体=恢宏，状态只叠加 |
| 场景是超远景俯视 | 只写分区属性，无动态/生活锚点 | 按②-4「活着的证据」清单给宏观痕迹（光斑/密度/飞行器/飞鸟） |
| 场景需要氛围 | 写"有生活气息/永不停歇/清幽"抽象词 | 具体化到锚点（竹竿晾蓝布衣/轻轨光轨/灵气光点） |
| 需要表达质感 | 写抽象质感词 | 拆成可见微表面、体积光与具体渲染特征 |
| 材质描写 | "冰凉石廊柱，青砖地面有磨损" | 三层描述法逐项（微表面=非塑料的冰裂漆纹等） |
| 用户要求竖屏短剧 | 默认 4:3 | 按平台改 9:16 |

## 失败降级

| 触发 | 处理 |
|------|------|
| 无图像生成器 | 交付「场景卡+五段式提示词+生成规格」，不虚构图像 |
| 原文场景描写不足 | 在内部选择保守、具体且可验证的视觉值，直接写入场景卡；不写“未描写”“默认”或“可替换”等控制说明 |
| 用户对生成图不满意 | 记录具体偏差（塑料感/尺度/色彩），回到对应段修正提示词 |
