# 剧情脚本数据模型与输出规范（script-spec）

> 本文档定义**剧情脚本/分镜的完整数据模型与输出模板**，供 SKILL.md 调用。
> **分镜 JSON 为主**（机器消费：审阅/机械校验/资产反推），markdown 渲染版并存（人读）。
> 对齐 ComfyUI-H3 工程的成熟机制：coverage 覆盖率 / continuity 边界锁 / assets 资产清单 / purpose 镜头目的 / 一镜一运镜。

---

## 一、设计原则

1. **对话按角色列出**：每句台词标注说话角色，供配音（TTS 分轨）与视频生成角色绑定直接使用。
2. **可演 > 可读**：动作/神态用「可拍摄的物理描述」，不是文学形容。
3. **情绪标注挂接 movie-create-drama-emotion**：每场标注情绪节点，用 10 情绪名 + 强度。
4. **保留原文因果**：改编可以删繁就简，但不得改变剧情因果、人物关系、明确台词语义。
5. **分镜 JSON 化**：分镜输出为结构化 JSON（含 purpose/continuity/coverage/assets），供机械校验与审阅闭环消费；同时渲染 markdown 版给人读。
6. **最终可表演台词**：`dialogue` 在入镜前完成一次必要的有限口语化后冻结；自然台词原样保留，明显 AI 味台词才有限调整。
7. **一镜一运镜**：每镜只一种主运镜，写起点-速度-终点，禁"推+摇"同用。

## 二、分镜 JSON Schema（主格式）

```json
{
  "storyboard": {
    "episode_title": "第1集",
    "meta": {
      "style_source": ".movie-create/style-guide.md",
      "style_id": "001_cyberpunk",
      "style_name": "Cyberpunk"
    },
    "duration_seconds": 120,
    "coverage": [
      {"beat": "{节拍名}", "source_text": "{原文摘录}", "shot_ids": ["{镜头ID}"], "status": "covered"}
    ],
    "shots": [
      {
        "shot_id": "{镜头ID}",
        "time_range": "0:00-0:05",
        "duration": 5,
        "scene": "{场景名}",
        "characters": ["{角色名}"],
        "props": [],
        "shot_size": "中景",
        "camera": "固定机位，从全景缓慢推近到近景后固定",
        "action": "{角色名}背靠廊柱缓缓滑坐，后脑靠墙，呼吸放缓，眼皮渐沉",
        "dialogue": "（旁白）{台词原文}。",
        "speaker": "旁白({角色名}内心)",
        "sfx": "环境鸟鸣，衣料摩擦",
        "mood": "疲惫·中度",
        "hook": "定调",
        "ref_anchors": [],
        "purpose": "{镜头目的：让观众建立什么初始状态}",
        "screen_direction": "",
        "continuity": {
          "start": {"position": "{角色名}靠西墙角落廊柱", "posture": "坐姿微倾", "gaze": "闭眼", "props": {}},
          "end": {"position": "{角色名}靠西墙角落廊柱", "posture": "滑坐更深", "gaze": "闭眼", "props": {}}
        }
      }
    ],
    "assets": {
      "characters": [{"id": "{角色名}", "description": "{身份/外貌一句话}", "shots": [1, 2]}],
      "scenes": [{"id": "{场景名}", "description": "{环境一句话}", "shots": [1]}],
      "props": [{"id": "{道具名}", "description": "{特征一句话}", "shots": [3]}]
    }
  }
}
```

### 字段说明

| 字段 | 说明 |
|------|------|
| `meta.style_source` | 完整风格定调权威来源；默认 `.movie-create/style-guide.md`，无风格时为 `null` 并使用中性描述 |
| `meta.style_id` | 96 风格库规范文件键；预设/已匹配风格填写，电影提炼或自定义为 `null` |
| `meta.style_name` | 风格展示名称，不作为模糊查找唯一依据；明确跳过风格时三个字段均为 `null` |
| `coverage` | 全片节拍→镜头映射，status: `covered` / `intentional_repeat` / `omitted_with_reason` / `nonvisual_context`；**禁止关键节拍无镜头落实（丢戏）** |
| `shots[].purpose` | 每镜必填：观众该注意什么 / 信息情绪变化 / 为什么切镜。禁空话（"展示场景"） |
| `shots[].continuity.start/end` | **边界锁**：位置/姿态/目线/持物/道具所有权。镜N end 必须 = 镜N+1 start；道具不得凭空出现/消失/换主 |
| `shots[].screen_direction` | 轴线：谁占画面左/右，未越轴；无多主体可省略 |
| `shots[].action` | **肢体级描述**（"慢慢抬手、用力攥地"），禁"奔跑/战斗/哭泣/愤怒"抽象动词 |
| `shots[].mood` | 情绪通过具体表情/手势/呼吸/视线呈现，非贴标签 |
| `shots[].hook` | **镜头钩子类型**：定调/信息揭示/情绪爆发/悬念/笑点/反转/压迫/转场。每镜必填——回答"这镜为什么抓人" |
| `shots[].ref_anchors` | **参考锚点**：本镜引用的资产/参考图（如 `["{角色名}", "{场景名}"]`），供视频生成的 `<Picture N>` 引用；空 = 无参考 |
| `assets` | 角色/场景/道具 + 出场镜头号；id 用中文原名，禁翻译禁缩写 |
| `duration` | 单镜 2-5 秒创作建议；镜头数 × 平均时长 ≈ 目标时长；最后一镜结束 = 目标时长；时间连续无空洞无重叠 |
| **分镜密度** | 15s ≈ 4 镜、30s ≈ 5-6 镜、60s ≈ 7-9 镜；**每镜只讲一个信息/情绪单元**（一个知识点/一个情绪点/一个动作） |

### 机械校验硬约束（validate_storyboard.cjs 强制，生成时一次过）

> 2026-08-23 全流程实测踩坑 5 条——以下字段若不按此写，机械校验会 FAIL，先看这里避免返工：

| # | 约束 | 错误写法 | 正确写法 |
|---|------|---------|---------|
| 1 | **`duration_seconds` 是顶层字段**（在 storyboard 内、coverage 旁），不是每镜 | 每镜写 duration_seconds | 顶层 `"duration_seconds": 23`，每镜只写 `duration` |
| 2 | **`time_range` 格式 `M:SS-M:SS`**，且区间长度必须 = duration | `"0-4s"` | `"0:00-0:04"`（4s）；结束秒必须与 duration 一致 |
| 3 | **资产引用字段是 `shots[].characters/scene/props` 数组**（validator 从这些字段提取"被使用"），不是只写 ref_anchors | 只在 ref_anchors 写 @角色 | 每镜显式写 `"characters": ["牛魔王"]`、`"scene": "花果山"`、`"props": []` |
| 4 | **`coverage[].status` 必填**，4 状态之一：covered / intentional_repeat / omitted_with_reason / nonvisual_context | 只写 beat + shot_ids | `{"beat": "...", "status": "covered", "shot_ids": [1,2]}` |
| 5 | **`ref_anchors` 是必填字段**（required 列表），空数组也算有 | 整字段缺失 | `"ref_anchors": []` 或 `["@{角色名}"]` |

**校验通过标准**：high=0 → PASS；medium（如单镜时长 2-5s 建议外）可接受，由审阅判断是否调整。

### 关键表演的字段落实

以下是生成时的思考维度，不是 Schema 字段。角色的意图、阻碍、策略和触发信息必须转译为现有 `action`、`mood`、`purpose` 或 `camera` 中至少一项可见结果：

- 关键对白要有说话者策略、回答前评估或倾听者反应；不要只写“说完”“听着”。
- 关键节拍和权力变化可通过站坐、距离、占据空间、目线、道具控制或镜头视角落实；不能只替换情绪标签。
- 纯站桩对话优先补充当前剧情已有的业务动作；若没有合理业务动作，保持简洁，不凭空增加节拍。
- 插入镜只能标点或强调已有 coverage 节拍，不得创造未覆盖事件。
- 多人反应需错峰，按先后、方向或强弱安排，避免机械同步。
- 普通镜头不要求完整罗列眼神、呼吸和肌肉变化；选择对当前控制点最有价值的可见动作即可。
- `dialogue` 仍由入镜前一次必要口语化定稿，写入分镜后冻结；本节不授权任何台词改写。

## 三、markdown 渲染版（并存，人读）

JSON 分镜生成后，渲染一份 markdown（从 JSON 转换，不手动维护）：

```
# 剧情脚本：{小说名} 第{集}

| 镜号 | 时间 | 景别 | 场景 | 角色 | 动作/神态 | 台词 | 情绪 | 运镜 |
|------|------|------|------|------|----------|------|------|------|
| 1 | 0:00-0:05 | 中景 | {场景} | {角色} | 背靠廊柱滑坐 | 旁白：{台词} | 疲惫·中度 | 缓推 |

## 资产清单
角色：{角色}（...）｜场景：{场景}（...）｜道具：{道具}（...）
```

## 四、填写规则

### 1. 分场
- 场景切换即换场；同场景时间跳变拆两场。

### 2. 台词
- `dialogue` 是入镜前一次 humanizer 检查后的最终可表演文本；自然台词原样保留，明显 AI 味才有限口语化。
- 必须保留说话人、人物关系、事实因果、专名数字、关键线索、承诺或否认、反转含义、情绪方向与表达意图；允许调整句式、语气词、停顿、拆句和不改变信息的压缩。
- 写入分镜后冻结；审阅、配音和视频导演只能继承，不得再次改写、翻译或口语化。机械工具仅作“近似文本一致性检查”。
- 标注说话人（speaker）；台词长度与镜头时长匹配（3 秒镜头不塞长对白）。内心戏转旁白，speaker 标「旁白(角色名内心)」。

### 3. 动作/神态
- 肢体级描述：起点→过程→终点；速度质感（缓慢/匀速/加速）；力度（轻柔/用力/爆发）。
- 禁文学修辞（心如刀割/怒火中烧）。

### 4. 情绪
- `movie-create-drama-emotion: 情绪·强度`；用具体表情/手势/呼吸/视线呈现。

### 5. 运镜
- 一镜一运镜；写起点-速度-终点；单场 ≤2 个运镜。

### 6. 机械校验配合
- 分镜 JSON 产出后，跑 `validate_storyboard.cjs` 做机械校验（时长归一化/资产反推/近似文本一致性检查/覆盖率核对）。

## 五、与下游的衔接

- **审阅**：movie-create-drama-review 读 JSON 分镜，审阅-修正-复核闭环直到 PASS。
- **角色/场景卡**：assets 中的角色/场景/道具引用对应的 movie-create-design-character / movie-create-design-scene 产物。
- **配音**：movie-create-drama-dialogue 从分镜 JSON 抽台词（speaker + dialogue + 情绪）。
- **视频**：分镜 JSON 的 camera/action/mood 是 movie-create-out-video-director 生成视频提示词的输入。
- **分镜块**：分镜 JSON 的 shots[] 是第十步 `03-分镜提示词.md` 的渲染输入——逐镜六段式（风格/场景叙事/构图/光影/材质/色彩），让用户确认分镜后再进视频；八宫格仅在用户明确请求时作为同一文件的可选小节。

### 六段式分镜提示词模板（第十步渲染用）

每镜一条，逐段输出（正文字幕中文，结构名保持固定段序）：

```
[镜N｜时间｜动作一句话]

**风格与美学设定：** 读取 `.movie-create/style-guide.md` 的母提示词（风格/媒介/颗粒/材质倾向/视觉语法），无风格时使用中性描述，不虚构参数。
**场景与叙事：** 场景 + 镜头内可见动作 + 台词（若有）。
**构图与空间关系：** 景别 + 机位角度 + 构图方法 + 主体面积比例 + 人物位置 + 留白/遮挡（景别×机位查 shot-size-library）。
**光影与曝光：** 主光动机/方向/光质 + 曝光/反差/阴影/高光 + 附 HEX（若风格指南提供）。
**材质细节：** 空间/道具/服装/毛发/地面的材质与反光 + 附 HEX。
**色彩系统：** 综合色调 + 主色/辅色/点缀色（中文 + HEX + 面积 + 明暗冷暖）。

**负面：** 仅写当前镜头风险与已确认风格的适用限制，不跨风格固化禁词；例如避免文字水印或结构错位。
```

- 末段负面 = `../../shared/negative-block.md` + 风格定调反向词 + 任务特有。
- 有参考图时正文不重复外观（沿用一致性铁律），只通过语义参考锚点锁定角色/场景外观，不覆盖叙事。
