# 万能电影风格提炼（标准版 V2.3）

## 🛠 工具依赖与适配（可插拔）

本 Skill 的方法论（证据驱动、HEX 强制、固定目录、暂停点）与具体工具无关；以下环节的工具可按当前运行环境替换：

| 流程环节 | 默认工具 | 可替换方案 | 当前环境适配 |
|---------|---------|-----------|-------------|
| 截图分析（视觉理解） | resource_prepare_and_analyze | 任意视觉理解 MCP（doubao-vision / glm-vision / qwen-vision） | doubao-vision MCP |
| 文本写入 | text_editor | 任意文本编辑工具 | write_file / edit_file |
| 图像生成 | GPT Image 2（默认，禁止 Nano Banana Pro） | Seedream / agnes-image / gpt-image-2 | gpt-image-2 skill（未来接 Seedream） |
| 资产绑定 | query_assets_info / manage_item_assets | 当前 runtime 的资产系统 | 无资产系统时跳过绑定并标注待办 |

**降级原则**：图像生成器不可用时，降级交付「六段式提示词 + 生成规格 + 场景还原简报」，不虚构图像产出；截图分析不可用时，不凭导演名/片名臆断风格。

## 规划阶段（Planner）
**适用边界、语言与影片美学定位**

- 启动时提供两条互斥入口：用户输入导演名、片名及导入的项目内影视截图（不得超过 **20 张**）以提炼新指南，或用户手动加载资产库中已有的风格指南。仅截图提炼路径需要截图；已加载指南成功后直接作为当前风格依据，不重复截图分析或新建指南。

- 截图是色彩、光影、构图、材质和场面调度的首要证据；导演名与片名用于理解影片语境，并必须写入每张图像提示词的全局风格首句，格式固定为：\[导演名\]《\[片名\]》电影美学风格。手动加载的指南也必须包含该定位句及对应的可见视觉规则。

- 全程使用中文：输入核验、截图记录、证据矩阵、风格指南、可视化剧本、Storyboard 描述、确认卡和图像提示词均须为中文；模型名、工具名、资产标识、原始导演名和片名除外。电影截图只用于分析，不能作为后续生成的 reference_image。

- 风格指南、可视化剧本、Storyboard、风格控制卡与图像提示词中的每个具体颜色，均须以 **HEX #RRGGBB** 表示；可在色值后补充明度、饱和度、冷暖、面积关系或叙事功能。禁止使用 HSV／HSB 色相、饱和度或明度范围表达颜色，也不得只写未附 HEX 色值的颜色名称。

  **风格指南固定目录与内容归位**

- 截图提炼时，新建的风格指南必须使用以下固定标题层级与顺序，不得增删、调换或合并主章节：# \[导演名\]《\[片名\]》电影风格指南、## 影片美学定位句、分隔线、## 一、截图证据清单（\[实际截图数量\]张）、## 二、跨图证据矩阵、## 三、风格特征优先级、## 四、全局视觉基线、## 五、条件性变体、## 六、反例与覆盖缺口、## 七、可复用禁区、## 八、风格一致性验收表、## 九、验证方案。标题中的实际截图数量必须与已确认素材数量一致。

- “一、截图证据清单”必须逐张使用文本记录，不得使用 Markdown 表格、合并多张截图、抽样或以摘要替代。每张截图以独立三级标题“### 截图［编号］”开始；以下字段各自独占一行：截图编号、时空条件、叙事功能、主体与环境的面积关系、可见光源与方向、曝光和反差、景别／机位／构图、空间几何、材质、服装／道具。色彩以四行“色卡方案—主色调／辅助色／点缀色／色彩关系”记录：前三项必须给出基于画面可见取样的中文颜色描述与对应 HEX #RRGGBB，色彩关系说明三者的面积、明度、冷暖、饱和度及可见叙事功能。胶片色彩特征以三行“胶片色彩特征—胶片色偏／对比度／肤色”记录。每个字段均须填值；不能由画面支持时，在该字段写“待验证”及原因，不得留空。截图中出现的任何饱和度特征均须如实记录；后续是否采用，取决于跨图证据强度、适用条件与已确认的风格指南。

- 二、跨图证据矩阵固定使用二级小节归纳色彩系统、光影系统、构图系统、空间与材质、人物与镜头；每节只写由当前项目截图证实的内容。

- 提示词写作与故事板设计的执行规则不作为风格指南章节输出，仍分别由本 Skill 的提示词、故事板与资产规则约束；目录缩减不得改变既有证据标准、全局排除项、试验流程、资产依赖或七段式提示词规则。

- 此固定目录只采用用户给出的信息架构，不得移植其中的示例影片结论、色彩数值、镜头偏好、禁区、验收条件、提示词内容、叙事规则或音频建议。当前项目所有具体规则仍必须完全来自已确认截图、已加载指南和既有 Skill 约束。

- 八、风格一致性验收表是生成前的规则完整性、可追溯性与提示词继承检查清单；它不得触发对已生成样图、角色图或多视图资产图的逐图视觉验收、质量评分或自动重生成。九、验证方案固定写明四张试验样图的覆盖条件与生成规格，并保留生成后直接交付的规则。

**阶段流程与暂停点**

🔴 **暂停点铁律：以下流程中的每一个「单选确认卡」都是强制暂停点——必须停下等待用户选择，禁止跳过、自动继续或替用户默认。**

 1. 🛑 启动时以单选确认卡提供“输入导演名、片名和截图”与“手动加载资产库中现有的风格指南”。选择前者时提示提供导演名、片名及截图；每次导入不得超过 **20 张**。选择后者时暂停等待用户手动加载已有指南。
 2. 🛑 截图提炼路径：核验导演名、片名、当批截图数量及输入清单，以单选确认卡暂停；只有用户选择“素材与片目信息无误，开始分析”后，才调用 **资源准备与分析**（resource_prepare_and_analyze）。手动加载路径：用户确认加载成功后，将该指南作为当前风格指南，直接进入第 5 步；不得要求截图或重新执行截图分析、风格指南创建或内部自检。
 3. 截图提炼路径：当前已确认截图分析完成后，立即将分析结果并入累计逐图记录与跨图证据矩阵，并直接进入第 4 步提炼风格指南；不展示、等待或要求额外截图相关确认。用户在分析开始前提交的各批截图均须先按第 2 步完成输入核验与分析；不得超过 **20 张**，且不得清空已确认截图的分析记录。
 4. 截图提炼路径：基于全部已确认截图，按“逐图记录 → 跨图证据矩阵 → 风格特征优先级 → 全局视觉基线 → 条件性变体”整理结果，再通过 **文本编辑**（text_editor）建立以片名命名、采用固定目录的完整中文风格指南。将“画面边缘亮度均匀、无暗角／无边缘渐暗”列为不可覆盖的全局排除项。无论截图是否出现，均不得将暗角或边缘渐暗写入正向风格规则、条件性变体或待验证假设；不执行两轮或其他内部自检流程。
 5. 🛑 将新建的指南或已成功加载的现有指南交付为当前风格指南，以单选确认卡暂停，提供“风格指南无误，生成四张试验样图”与“修订风格指南”。对手动加载的指南，仅在用户选择修订时更新受影响规则、控制项、插槽、模板或故事板设计系统；任何版本不得允许暗角或边缘渐暗成为风格特性。
 6. 用户确认后，调用 **媒体生成器**（media_generator）生成日间室内、夜间室内、日间室外、夜间室外四张无参考风格试验样图，固定为 **16:9、2K**。四张图须分别还原已确认截图中对应时空条件的一个目标场景：从逐图记录提取并以文字继承该场景可见的空间构成、主体与环境面积关系、关键陈设与材质、人物动作与站位、构图／景别及光源逻辑；截图本身绝不作为 reference_image、keyframe 或其他生成输入。每张样图以无具体身份指向的人物替代原片角色与演员肖像，不生成原片标志或台词。若任一时空条件没有可用的已确认截图，暂停并要求用户补充或指定对应场景。四图依据已确认的色彩策略生成后直接交付，不调用 **资源准备与分析** 做逐图视觉验收、质量评分或自动重生成。
 7. 🛑 交付样图后，以单选确认卡暂停，提供“样图已生成，仅交付风格方法”“样图已生成，进入故事板开发”“修订风格指南或重做样图”。用户选择修订时，按其明确反馈处理，不以逐图视觉验收结果触发修改。只有选择故事板开发后，才要求用户提供完整剧本；未收到完整剧本不得创建新故事的 key_element、可视化剧本或 shot。
 8. 收到完整剧本后，先调用 **资源准备与分析**（resource_prepare_and_analyze）提取人物、场景、重要道具、叙事段落、时空、行动、明确对白与连续性约束；再通过 **文本编辑**（text_editor）建立或更新 Final_Video_Spec.md，锁定剧本目标、画幅、时长、语言、影片美学定位句、已确认全局视觉基线、色彩策略及可视化剧本边界。
 9. 调用 **故事板设计器**（storyboard_designer）将剧本转化为不改变剧情因果和明确台词的中文可视化剧本，并建立 element character、element scene、关键道具、shot 与必要的 audio_layer。先建立角色、场景和道具资产，再按叙事段落分批生成故事板分镜图。
10. 🛑 每名角色先生成 **3:4 纯色背景正面半身身份照**。不对该图或后续多视图资产图进行逐图视觉验收、质量评分或自动重生成；但须以单选确认卡等待用户确认该半身照可作为角色资产。用户确认后，立即注册并绑定该半身身份照，并仅以它作为 reference_image 自动生成 **3:4 多视图资产图**；不设置用户上传、确认或核验正面全身照的环节。全部所需资产可用后才生成依赖它们的分镜图。

**依赖与交互约束**

- 截图提炼路径中，输入确认先于分析；当前已确认截图完成分析后直接建立风格指南，不设置额外截图的确认卡或暂停门。用户在分析开始前分批提交素材时，每批均须完成输入核验与分析，每批不得超过 **20 张**，且累计记录不得清空。指南先于试验样图。手动加载路径中，指南加载成功即作为当前指南进入指南确认。两条路径均须在样图生成后，才可进入新故事开发；完整剧本分析和 Final_Video_Spec.md 先于可视化剧本与 Storyboard；所需元素资产先于相关分镜图。
- 每个暂停点使用可直接执行的单选确认卡，并保留明确的修订选项；不要求用户手动输入“确认”或“继续”。角色半身身份照得到用户确认后，不再暂停或等待任何全身照，直接进入多视图资产图生成。
- 样图和角色图生成后不执行逐图视觉验收。角色半身身份照的用户确认仅是其能否作为角色资产被采用和绑定的准入，不构成脸部、发型、体态、服装、鞋或道具的二次一致性核验；只在用户明确要求时重生成受影响的资产及其依赖项。


## 截图分析（Multimodal Analyze）
**影视截图的可审计风格分析**

- 仅分析用户确认的截图，并以中文输出。每次导入的截图不得超过 **20 张**，累计分析数量不限；逐图记录可见事实，不从单张画面、导演名、片名或概括性形容词推导整部作品风格；无法由截图或可靠影片语境支持的内容必须标为“待验证假设”。当前已确认截图分析结束时，交付逐图记录、累计截图数量和已更新的跨图证据矩阵，不建立、草拟或交付风格指南；由规划阶段直接衔接风格指南提炼，不输出或等待额外截图相关确认。
- 为日间室内、夜间室内、日间室外、夜间室外各建立一条“样图场景还原简报”：关联对应的已确认截图编号，逐项提取可见的空间结构、主体与环境面积关系、关键陈设与材质、人物动作与站位、景别／机位／构图、主光动机与方向及已确认的 HEX 色彩关系。该简报仅作为无参考 TextToImage 的文字依据，不能携带或绑定截图为 reference_image、keyframe 或其他生成输入；若某一条件没有已确认截图，明确标为缺口并要求补充或指定。
- 风格指南交付时严格采用固定目录：标题与“影片美学定位句”在前，随后按“一至九”的固定章节输出。截图清单的数量字段必须写已确认的实际数量；其中“一、截图证据清单”以每张截图一个独立的文本记录呈现，不使用 Markdown 表格，一张截图不得与其他截图合并、抽样或以摘要替代；跨图证据矩阵固定细分为色彩系统、光影系统、构图系统、空间与材质、人物与镜头。提示词写作与故事板设计规则不作为风格指南章节输出，而由对应的执行规则承接。只采用该目录，不得引用用户提供的示例指南中的任何具体结论或规则。
- 为每张截图输出可直接写入风格指南的一组完整文本记录：先以“### 截图［编号］”分隔，再将截图编号、时空条件、叙事功能、主体与环境的面积关系、可见光源与方向、曝光和反差、景别／机位／构图、空间几何、材质、服装／道具各写一行。色卡方案必须分四行输出“主色调／辅助色／点缀色／色彩关系”：主色调、辅助色与点缀色均须包含从可见画面取样分析得到的中文颜色描述及相应 HEX #RRGGBB；色彩关系须说明各色的面积、明度、冷暖、饱和度和可见叙事功能。胶片色彩特征另分三行写明“胶片色偏／对比度／肤色”。所有字段均须填值；证据不足时在对应行写“待验证”及原因。随后形成跨图证据矩阵，明确高频共性、条件性规律、例外和未覆盖条件。
- 在矩阵后建立“风格特征优先级”：仅将跨图稳定且高置信的可见规律列为不可妥协的全局锚点；将只在特定时间、空间或叙事压力下成立的规律列为条件性变体；将低置信规律保留为单一测试变量。影片美学定位句须与这套证据驱动的规则一起写入指南和提示词，不能据其虚构不可见属性。
- 截图中出现的色彩与饱和度特征必须如实记录为可见事实。仅将跨图稳定且高置信的规律提升为全局锚点；仅在明确的时间、空间或叙事条件下成立的规律归为条件性变体；低置信规律保留为单一测试变量。后续的色彩基线、元素、shot 与生成提示词均须忠实继承已确认的适用规则。

**色彩、光影与风格控制**

- 色彩系统须以 HEX #RRGGBB 写明主色、辅色、强调色、近中远景面积关系、明度／饱和度／冷暖关系、强调色载体及其可见叙事功能；光影系统须写明主光动机和方向、光质、色温、补光或反射、曝光关系、反差、阴影、轮廓光和实用光的可见功能。禁止使用 HSV／HSB 色相、饱和度或明度范围，亦不得以没有 HEX 色值的色名代替具体颜色。无论截图是否存在画面四周暗角或边缘渐暗，均不得将其写入用于后续执行的色彩、光影、构图、材质、全局锚点、条件性变体或待验证假设。
- 在“风格一致性验收表”中输出可复核的生成前风格控制清单：全局锚点逐项标注优先级、证据来源、可见判据和允许变化；所有颜色判据均使用 HEX #RRGGBB，并检查色彩关系是否忠实继承已确认的证据。“验证方案”的条件设计须覆盖影片美学定位、人物与环境关系、综合色彩关系、主光逻辑、反差与阴影、构图距离、空间材质、情绪表达，以及画面边缘亮度均匀、无暗角／无边缘渐暗。该清单仅检查规则是否可执行，不分析或评分已生成图片。

- 除固定多视图资产图的版式正文外，样图、key_element 图和故事板分镜图均采用六段式。主结构严格按下列顺序逐行输出，每行使用“**结构名：** 内容”；其中“色彩系统”可在其后另起行列出主色调、辅助色、点缀色、色彩关系与胶片色彩特征。不要堆叠相互冲突的光源、色彩、机位或情绪指令。

**六段式提示词结构**

1. **风格与美学设定：** 写明已确认的电影美学定位、全局视觉基线、可见的媒介／颗粒／光学质感、材质倾向与视觉语法。只描述已有证据支持的属性，不虚构胶片型号、年代工艺或技术参数。
2. **场景与叙事：** 写明时空条件、具体空间、叙事主体、可见动作、人与环境关系和需要传达的可见情绪。样图采用无具体身份人物；已绑定角色则继承其确认的外观与当前剧情状态。
3. **构图与空间关系：** 写明景别、机位或角度、构图方法、主体与环境面积比例、人物位置、空间几何、透视纵深、留白、遮挡、框景元素及关键物体之间的视觉层次。
4. **光影与曝光：** 写明主光动机、方向、光质、环境补光或反射、曝光、反差、阴影、高光、轮廓光及其可见叙事作用。任何光色或反射色均附 HEX #RRGGBB，且只能使用已确认或单独标为待验证的规则。
5. **材质细节：** 写明关键空间、道具、地面、服装与环境表面的材质、反光和状态，以及支撑叙事的可见细节；涉及颜色时附 HEX #RRGGBB，并继承相应 key_element 的状态与连续性。
6. **色彩系统：** 先概括综合色调与饱和度关系，再逐项列出主色调、辅助色、点缀色与色彩关系。每项颜色必须含中文描述、HEX #RRGGBB、画面面积、明度、冷暖、饱和度、载体及可见叙事功能；最后写明胶片色偏、对比度与肤色。高饱和色调、大面积色块或强调色只在截图证据或已加载指南明确支持时采用。

- 故事板分镜图先继承对应 shot 的中文可视化剧本与风格控制卡，再按六段式写明可见行动、人物关系、空间调度、景别、机位、构图／遮挡／留白、角色位置、可见光源、以 HEX #RRGGBB 表示的色彩面积与饱和度关系、材质和连续性要求。reference_image 只用于锁定指定角色、场景或道具，不得覆盖该 shot 的叙事和镜头设计。

## 🛟 失败模式与降级协议

| 触发条件 | 一线处理 | 仍失败兜底 |
|---------|---------|-----------|
| 用户缺导演名或片名 | 在输入核验确认卡上列出缺失项，要求补全 | 不凭片名臆断导演，暂停等待补全 |
| 截图超过 20 张 | 拒绝超额导入，提示分批 | 每批核验+分析，累计记录不清空 |
| 截图未覆盖四类时空（日间室内/夜间室内/日间室外/夜间室外） | 样图生成前暂停，要求补充对应截图或指定场景 | 只生成已覆盖条件的样图，缺口如实标注 |
| 单张截图证据不足 | 对应字段写「待验证」及原因，不留空 | 跨图矩阵标为低置信，不提升为全局锚点 |
| 手动加载路径无指南/加载失败 | 确认卡走「修订」分支 | 不退回截图分析路径，暂停等待加载 |
| 图像生成器不可用 | 降级交付「提示词+生成规格+场景还原简报」 | 明确记录工具缺失，不虚构图像产出 |
| 资产绑定工具不存在 | 跳过绑定，标注待办 | 未确认资产不用于分镜图生成 |
| 截图被要求作 reference_image | 拒绝（截图仅作分析证据） | 用文字还原场景，样图无参考生成 |

## 🔴 反例与黑名单（危险动作红灯表）

| 触发条件 | 🚫 危险动作（不要做） | ✅ 正确替代 |
|---------|---------------------|-----------|
| 需要表达颜色 | 用 HSV/HSB 范围或仅写颜色名 | 强制 HEX #RRGGBB + 明度/饱和度/面积/叙事功能 |
| 截图分析 | 由导演名/片名推导风格结论 | 只从已确认截图提取证据，其余标「待验证」 |
| 生成样图/资产/分镜 | 用原始截图做 reference_image | 截图仅作分析证据，样图用文字还原 |
| 任意阶段 | 将暗角/边缘渐暗写入风格规则 | 列为不可覆盖的全局排除项 |
| 图像生成后 | 逐图视觉验收/质量评分/自动重生成 | 直接交付，仅用户明确要求时修订 |
| 角色资产确认 | 要求正面全身照环节 | 半身照确认后直接生成多视图资产图 |
| 资产绑定 | 从文件标签推断绑定或用 ID 模板 | 用实际 Storyboard 目标 ID，保留完整 asset_bindings |
| 待验证假设 | 当作全局锚点使用 | 只能作为独立、可调整的测试参数 |
