# 视频提示词编译前规划参考规范

本参考只在 out-video-director 需要把素材编译成视频提示词时读取。它把生产决策与模型措辞分开：先检查输入、锁定可见事实和控制重点，再生成目标模型正文。它不是新的 Skill、不是分镜 JSON Schema，也不替代已有的场景布局蓝图。

## 一、输入与输出

规划至少读取（不读取 03 分镜脚本图提示词）：

- 目标模型与任务类型：Seedance 或 H3；文生、参考图、编辑、延长或组合；
- 已审阅分镜及当前镜头范围；
- `camera`、`action`、`mood`、冻结的 `dialogue`、`ref_anchors`、`hook`；
- `storyboard.meta.style_source`、`style_id`、`style_name`；
- 已有角色卡、场景卡、空间蓝图、`screen_direction` 和 `continuity`；
- 用户上传或明确提供的图片、视频、音频及其语义用途。

默认手动槽位模式下，复杂任务先输出人读的 `.movie-create/video-plan.md`，规划锁定后输出 `04-视频提示词.txt`；文首只建立一次 `语义名称 = [图片槽位]` 映射，后文只写语义名称。轻量单镜任务只做内部最小检查，直接转为 `LOCKED` 并输出 TXT，不强制生成规划文件。方括号由用户手动附加真实图片，不得填 Markdown、蓝图、ASCII 或提示词文本，也不代表图片已经存在。只有用户明确要求自动平台适配时，才要求 `reference-assets.json` 标记 `verified` 且 `video-config.json` 当次 binding 为 `bound`，并由目标模型编译标签：H3 使用 `<Picture N>`，Seedance 使用 `<图片N>`；语义别名不得泄漏进自动模式模型正文。自动平台适配模式无真实绑定图片时必须使用无图 T2V，不得伪造标签；手动槽位模式由用户实际 @ 图片，插件不判断资产存在性或自动降级。

## 二、状态机

### AUTO-LOCK

轻量路径：单镜/单主体，模型和任务明确，无素材映射歧义、空间歧义或镜组歧义，用户没有要求先看规划。只做内部最小检查，直接进入 `LOCKED`，只输出最终 TXT。

复杂路径：目标模型、镜头范围、任务类型和风格路径明确；所有必要资产能够一一映射；空间、表演和镜组边界没有影响结果的重大歧义。先写简洁规划摘要，摘要完成后进入 `LOCKED`，再生成最终提示词。

### NEEDS-CONFIRMATION

以下通用条件任一命中就只输出规划并停止：

- 自动平台适配模式下，一个文件或上传序号可能对应多个角色、场景或道具；
- 自动平台适配模式下，依赖一致性的必需真实参考素材缺失；
- 已选风格但 `style_source` 或权威定义不可读；
- 两人以上互动时，站位、目线、遮挡、入画方向或轴线有实质歧义；
- 关键道具的持有人、位置或状态不明确；
- 用户要求合并镜头，但连续时间单元、总时长或边界不明确；
- 同一情绪标签存在会导致不同表演结果的合理解释；
- 用户明确要求先看规划、不写提示词。

任一模式此状态下不得出现 H3 字段、Seedance 六段式、时间轴正文或任何可以直接粘贴使用的最终提示词。`target_model=null`、用户只说“继续”以及通用条件中的风格/空间/镜组/情绪歧义均保持此状态；自动模式的资产缺失或歧义也保持此状态，手动槽位模式不因未附图进入此状态。只列出会改变生成结果的确认问题，一次不超过三个，优先一个最小问题。

### LOCKED

用户确认规划，或 AUTO-LOCK 条件全部满足后，状态才为 `LOCKED`。只消费锁定内容编译最终提示词。若用户随后修改空间、资产映射、风格权威来源或镜组边界，当前锁定失效，回到规划阶段。

## 三、资产映射

默认手动槽位模式先写一次：

```text
## 参考资产映射
- 角色A = [角色A设定图]
- 场景客厅 = [场景客厅场景图]
```

后文只写角色A、场景客厅；不在默认示例中出现文件名、上传序号、平台标签或账本状态。

### 仅 automatic_platform 的内部映射表

先建立一张人读映射表：

| 语义资产 | 类型 | 文件或上传序号 | 用途 | 模型标签 | 状态 |
|---|---|---|---|---|---|
| 角色A | 身份参考 | 角色A.png | 身份与服装一致性 | Seedance：`<图片1>`；H3：`<Picture 1>` | 已确认 |
| 场景客厅 | 场景参考 | 场景-客厅.jpg | 空间布局与材质 | Seedance：`<图片2>`；H3：`<Picture 2>` | 已确认 |

自动平台适配模式的映射状态来自账本/本次绑定：`bound`、`missing` 或 `ambiguous`；只有 `verified + bound` 才允许模型标签。默认手动槽位模式只验证文首 `语义名称 = [图片槽位]` 的名称唯一、覆盖所需角色/场景，且槽位未填 `.md`、蓝图、ASCII 或提示词文本；不要求 `attached`、`verified` 或 `bound`。不能把编号顺序当成语义事实。已有参考图的外观和环境不要在正文大段重复，只保留动作、状态和一致性约束。

参考职责按用途分层：身份参考控制人物一致性，场景参考控制空间地理，动作视频参考控制动作或运镜，风格来源控制视觉语言；风格不能覆盖人物、空间、动作、目线和光向硬约束。

## 四、空间阻挡触发

仅在以下情况展开空间关系：两个或更多人物互动；关键道具位于桌面、门口、手中等位置敏感处；有入画、出画、绕行、遮挡或越轴风险；相机位置决定谁能看见谁；人物位置会在镜组内改变。

优先继承已有 scene-layout、`screen_direction` 和 `continuity`。规划至少写清：

- 画面左/中/右及前/中/后景；
- 人物面朝与目线目标；
- 关键道具和人物或表面的关系；
- 移动方向及起止状态；
- 相机位于轴线哪一侧；
- 位置改变后的下一空间状态。

ASCII、表格或短列表均可，不要求 SVG。空间关系被用户修改后，必须重新规划和锁定，不能凭记忆直接改最终提示词。

## 五、表演控制点

关键对白、谈判、对峙、审讯、试探、隐瞒、权力翻转、情绪峰值、反转或多人反应容易同步化时，规划只提取能控制画面的信息。对话镜尤其要记录说话者策略、回答前评估和倾听者反应，但不改写冻结台词：

- 目标：角色想让对方做什么；
- 障碍或代价：为什么不能直接做到；
- 策略：施压、试探、安抚、回避或诱导等可行动动词；
- 触发：什么新信息使策略改变；
- 可见变化：停顿、呼吸、姿态、目线、距离或业务动作；
- 倾听：对方台词未结束时的评估或反应；
- 状态惯性：切镜后仍需保留的紧张、伤痛或决心。

可选表演控制项不是每镜必须完整罗列的检查表。情绪标签不能机械映射成同一组生理词；峰值镜只选一至两个高控制价值反应。群体按先后、方向或强弱错峰。复杂动作可规划为准备、执行、结果三个连续状态，但必须保留起点、过程、终点和环境反馈。切镜后重新确认当前人物、道具、伤痕、光向和情绪状态。`dialogue` 已冻结，规划只能标注其表演方式，不能翻译、改写或再次 humanize。

## 六、镜组边界与密度

默认逐镜一条提示词。只有目标模型支持内部切镜、用户明确需要合并，且角色集合、地点子区域、连续情绪/时间单元、总时长和控制重点都相容时，才允许合并。

必须拆分：地点变化；关键人物进出；独立插入镜或反打承担戏剧标点；表演段需要单独保留节奏和时长；镜头设置根本变化；合并后会挤掉关键动作、台词或空间关系。

压缩顺序：

1. 保留身份、首帧、空间、目线、手和道具状态；
2. 保留核心动作顺序、冻结台词和 continuity；
3. 保留直接影响结果的光向、环境反馈和声音；
4. 压缩重复外观、非关键服装细节和未激活背景元素；
5. 删除纯装饰性形容和泛化电影感套话。

## 八、六个最小例子

### 例一：简单单人近景，AUTO-LOCK

输入：单人近景，镜头范围明确，角色A只有一张身份图，场景无位置关键道具，目标为 Seedance。

自动平台适配模式内部最小检查（目标模型为 Seedance）：角色A（Seedance：`<图片1>`）的主体、单镜范围、动作和冻结台词明确，无空间歧义或素材映射歧义；状态由轻量 `AUTO-LOCK` 直接转为 `LOCKED`，只输出 `04-视频提示词.txt`。若目标模型改为 H3，必须将该引用解析为 `<Picture 1>`，不得把未解析的别名交付到最终正文。手动槽位模式只需验证文首映射结构。

### 例二：双人加道具，NEEDS-CONFIRMATION

输入：角色A和角色B在桌边争执，桌上有一把关键钥匙；两张人物图和一张场景图已提供，但分镜没有明确谁在画面左侧、谁持钥匙。

规划：列出三项资产映射；标记双人、桌面道具和轴线为高风险；不写模型正文。只问：“请确认角色A位于画面左侧还是右侧，以及钥匙由谁持有？”等待用户确认后重新锁定。

### 例三：资产映射歧义，NEEDS-CONFIRMATION

输入：上传了 `image1.png`、`image2.png`，用户只说“一张是角色、一张是场景”，没有说明哪张对应什么。

规划：状态 `NEEDS-CONFIRMATION`；不按上传顺序猜测；只问：“请确认 image1.png 是角色参考还是场景参考？”确认前不得输出任何最终提示词。

### 例四：确认后进入 LOCKED 并生成

第一次：双人站位未定，输出 `.movie-create/video-plan.md`，状态 `NEEDS-CONFIRMATION`，只问“角色A在左还是右”。用户确认“角色A在左、角色B在右”后，更新空间映射，状态变为 `LOCKED`，再输出 `04-视频提示词.txt`；确认前不提前附正文。

### 例五：H3 从规划到最终字段

自动平台适配模式规划锁定：目标模型 H3，角色A映射为 `<Picture 1>`，冻结台词为“我知道了。”。最终只保留最小结构：

```text
integrated_multimodal_description: <Picture 1> 抬眼，停顿后说：“我知道了。”
overall_soundscape: 室内安静，能听见短促呼吸。
non_diegetic_music: N/A
```

`<Picture 1>` 与冻结台词原样保留，不把人读别名写进正文。

### 例六：允许合并与必须拆分

允许合并：同一房间、同两名角色、连续一段对话，第二个镜头只是同一情绪单元内的轻微反应变化，目标模型支持内部切镜且总时长可控；先写“连续镜组”，再编译一条提示词。

必须拆分：第一镜在客厅，第二镜转到门外，或关键人物进出、独立插入镜、全新机位改变空间关系；分别规划和编译，不能为了减少提示词数量强行合并。

## 九、回退与质量检查

编译前检查：状态为 `LOCKED`；目标模型和任务类型明确；风格路径可读或用户明确跳过；`dialogue` 与分镜一致；空间、目线、道具、首帧和 continuity 未丢失；关键对话的策略或倾听反应已按需落实；峰值镜没有堆叠过多生理反应；失败约束只针对本镜风险；最终文本没有因压缩删除高控制价值信息。自动平台适配模式另检查所有必需映射已确认且正文标签符合目标模型、语义别名没有泄漏；手动槽位模式检查文首映射结构，正文只用语义名称且不含尖括号标签。

发现事实缺失、映射冲突、空间冲突、风格来源缺失或超出当前任务范围时，停止编译并回到规划阶段。不要在 OUT 中偷偷修改剧本事实、冻结台词或风格权威来源；这些问题应退回对应上游处理。
