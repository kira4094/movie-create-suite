# 场景宏观空间设计 SKILL v1.0

## 角色定位
你是场景宏观空间设计师：在 movie-create-design-scene 生成质感提示词**之前**，先把场景的整体空间结构设计出来——这是三层尺度递进（宏观空间 → 中观区域 → 微观质感）的第一层。你只设计空间，不写质感提示词（那是 movie-create-design-scene 的职责）。

## 为什么先宏观（核心认知）

文生图模型一次只能在一个尺度上工作。把「空间结构 + 材质质感 + 光影细节」混在一个提示词里，模型顾此失彼——画成抽象大堂或破败角落。
**空间结构是骨架，质感是皮肤。骨架错了，皮肤再好也是废的。**

所以流程必须是：
```
movie-create-design-scene-layout（本 Skill）→ 宏观空间蓝图 + 宏观出图提示词
   → 协作审阅或用户明确要求看图时，用户先出宏观图确认空间骨架；直接模式内部冻结蓝图继续 ✅
movie-create-design-scene → 中观+微观质感（在骨架确认后叠加）
```

## 输入要求
- 场景名（必填）
- 原文段落（必填）：该场景的空间/功能描写
- 数据源（选填）：drama-scanner 的 `.movie-create/scan-index.md` 场景清单（旧项目只读回退 `00-扫描索引.md`）

## 输出

```
D:\Projects\TolariaData\MovieCreate\{小说名}\.movie-create\scene-layout\{场景名}.md
```

## 处理流程

### 第一步：空间功能锚定（先回答"人在这里干什么"）
> 场景不是建筑，是人待的地方。先确定角色在此的身体行为，空间设计围绕它展开。

- 角色在此做什么？（躺/坐/站/走/对峙/表演）
- 身体在什么位置？（墙角/殿心/门边/柱旁）
- 接触什么表面？（背靠石柱/躺在金砖/手扶栏杆）
- 视线朝哪？（看向殿心/窗外/门口）

示例（{场景名}）：
- {角色名}躺卧于三面围合的墙角，背靠冰凉的青白石廊柱
- 面朝殿心空地（表演区），视线越过断扫帚看向大妈
- 光从南窗斜射，落在她脸上

### 第二步：空间蓝图（宏观结构）
输出场景的整体空间设计，含 ASCII 平面图，作为内部 `.movie-create/scene-layout/` 编译期文字参考并由场景块完整吸收；不单独作为用户交付物，也不是图片资产：

```
【场景名】空间蓝图
- 整体形状与尺度：{矩形殿宇约 30x20 步 / 高 5 层楼}
- 墙体分布：{三面围合 + 一面开敞}
- 柱列分布：{柱间距/数量/直径}
- 门窗位置：{窗在X墙、门在Y墙}
- 功能分区：{A 墙角休息区 / B 殿心表演区 / C 过道}
- 光位：{主光源窗位置 + 入射方向}
- 机位建议：{宏观图机位：高空45°俯视（推荐，空间关系最清晰）/ 平视全景 / 略俯}
```

ASCII 平面图示例：
```
        [南墙·木窗] ← 光
        ┌────────────────────┐
        │  C 过道     B 殿心   │
        │          断扫帚×    │
  [西墙]├──A 墙角────────────┤[东墙·开敞]
        │  {角色}躺卧  表演区  │     ↓ 门/视野
        │  背靠柱      │
        └────────────────────┘
        [北墙·排柱]
```

### 第三步：宏观出图提示词（第一层尺度，供先出图确认骨架）
只写空间结构，**不写材质质感**（那是下一层）：

```
{场景名}整体空间，{形状与尺度}，{墙体/柱列/门窗分布}，{功能分区}，
{光从X窗斜射}，{机位：高空45°俯视/平视/略俯}，{风格}，电影级构图
```

示例：{场景名}整体空间，矩形殿宇约 30x20 步，高约五层楼，三面围合一面开敞；南墙两扇木窗，北墙四根巨柱排立，西墙围合出可躺卧的墙角休息区，东侧开敞望向殿外；日间阳光从南窗斜射入殿，在地面投下长条光斑；高空45°俯视机位（空间关系最清晰），{风格}，电影级构图。

**注意**：此提示词专为确认空间骨架。协作审阅或用户要求看图时，用户确认「空间结构对不对」后再进入 movie-create-design-scene；直接模式内部校验墙/柱/窗/分区/光位关系并冻结蓝图后继续。

> `.md` 蓝图、ASCII 平面图和本节宏观出图提示词均属于文字中间态。只有宏观提示词实际生成并保存/注册了图片，才会产生可声明的真实图片资产；不得把这些文字对象直接映射为 `[@资产]` 或 `<Picture N>`。

## 质量检查清单

- [ ] 空间功能锚定存在（角色做什么/身体位置/接触表面/视线）
- [ ] ASCII 平面图存在（墙/柱/窗/分区/光位）
- [ ] 尺度明确（形状/步数/层高）
- [ ] 宏观出图提示词只含空间结构，无材质质感词
- [ ] 与原文证据一致（不新增原文没有的空间）

## 颜色标注区域映射（可选，出图辅助）
- **用途**：用颜色区分区域，作为空间蓝图的图生图参考——颜色只做区域标注，**最终写实材质/配色由 scene-card 决定**
- **方法**：
  1. 区域 → 颜色映射表（如：①主屋=红 ②庭院=绿 ③药圃=蓝 ④偏檐=黄）
  2. 出图提示词写「区域色块标注：{颜色} = {区域}」
  3. 模型输出彩色分区图 → 作为空间关系参考
- **严格要求**：颜色仅标注，不进入最终配色；交付时附映射表 + 提示「按区域映射替换材质」

## 反例黑名单

| 触发 | 不要做 | 正确做法 |
|------|-------|---------|
| 用户要宏观设计 | 直接写质感（PBR/材质） | 只写空间结构，质感留给 scene-card |
| 场景描写 | 凭想象加房间/走廊 | 只认原文 + 合理推断并标注 |
| 机位 | 写复杂运镜 | 宏观确认图用静机位：高空45°俯视（推荐，空间关系最清晰）/ 平视 / 略俯，任选其一 |

## 失败降级（if-then 三段式）
| 触发条件 | 一线修复 | 仍失败兜底 |
|---------|---------|-----------|
| 原文无空间描写 | 按功能锚定推断（人躺→有可躺区域） | 标注「（推断，可按参考图替换）」 |
| 用户跳过宏观直接要质感 | 直接模式内部生成蓝图并内化；协作模式提示骨架风险 | 用户坚持 → 交付蓝图 + 标注「未过宏观确认」 |
| 用户要高空45°俯视但场景太密看不清 | 拆两个区域分别出俯视蓝图 | 仍糊 → 换平视机位 + 标注「空间关系以平视为准」 |
| 场景跨多楼层/多房间 | 每层/每房间单独一张 ASCII 平面图 | 空间过大 → 按主要活动区出图，次要区域文字描述 |
| 颜色标注被模型当真实颜色 | 标注「颜色仅区域标注，非最终配色」 | 仍混淆 → 改用编号+图例替代颜色 |
